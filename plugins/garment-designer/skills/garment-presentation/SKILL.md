# 服装设计方案

把已有款式变成可以直接讲解的方案。默认简洁的 16:9 图文页面，突出设计本身；用户只要一种格式就只导出该格式，泛指“方案包”时可同时交付 PDF、PPTX、HTML。

## 使用

1. 发现插件工具 `garment_project`、`garment_present`。从当前对话取得准确项目，用 `garment_project get` 读取完整设计和版本；不明确时先 `list`，不要任意选别人的项目。没有设计时先使用 [garment-design](../garment-design/SKILL.md) 起稿。
2. 按用户的讲解目标组织方案。通常可包含：设计方向、整体正背面、两三个关键细节、配色、方案总结。页数随内容调整；省略没有设计的视图。默认不做生产工艺、尺寸表或成本估算。区分已画出的几何、描述中的材质意向和待确认建议，不能把效果设想写成已验证事实。
3. 用 `garment_present`，指定 `project_id`、刚读到的 `revision` 和 `formats`。它会固定到这个版本，不受后续改款影响。最快出稿可以省略 `slides`，直接基于已保存描述生成；用于正式讲解时由你写每页标题、要点和备注，详见 [导出参数](references/export.md)。不要要求普通用户编辑 JSON。
4. 查看返回的 `files` 和 `errors`。部分格式失败时交付已成功文件，说明缺项；不要把缺失的 PDF 当成已生成。检查至少整体、细节和文字最多的页面：款式是否完整、颜色和标注是否对应、中文有无缺字、文字是否溢出。备注保存在 PPTX、HTML 和 `outline.json` 中，PDF 正文只保留讲解要点。
5. 用真实返回路径引用文件，让用户直接打开或下载；HTML 以文件/可视化引用交付，不自动弹出交互 App。简要标注设计版本和格式。路径属于插件所在主机，云端文件通过宿主远端预览/传输交付，不能当成本机路径读取。

## 真实格式与边界

- PDF：矢量线条、可搜索文字、嵌入字体，适合分享或打印。
- PPTX：文字可编辑，款式图以 SVG 嵌入并带真实 PNG 兼容预览。支持 SVG 的 PowerPoint 可保留清晰缩放；这不等于所有软件都能把路径直接拆成原生编辑图元。交付的是 `.pptx`，不是旧版二进制 `.ppt`。
- HTML：单文件离线演示、键盘翻页、讲解备注、明暗主题；内嵌 SVG，不把整页截成图片。导出目录也保留独立 SVG 和方案大纲。
- 三种格式使用同一份设计数据和讲解内容；不调用图片生成、模型服务、外部上传或收费接口。生成效果图不是导出的前提。
- 不擅自修改设计去配合讲稿。用户要改款时先修改并保存新版本，再导出对应版本。

## 环境不足时

优先走 MCP 工具，运行时只需 Node 22+，导出依赖已随插件打包。PDF 另需覆盖文稿字符的字体，常见 Windows/macOS 字体和 Linux Noto CJK 会自动探测；缺字体时 HTML/PPTX 仍可生成。可使用已安装字体配置 `GARMENT_PRESENTATION_FONT`，系统字体安装按宿主权限流程处理，不隐式安装软件。

宿主无法调用 MCP 但可以在插件所在机器执行命令时，使用本 Skill 的 `scripts/export.mjs`，参数见 [导出参数](references/export.md)。不硬编码插件安装路径，不在另一台机器猜测设计数据目录。
