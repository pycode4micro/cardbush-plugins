# 切片与时间轴

FFmpeg 是智能体执行的本地媒体处理程序；ffprobe 读取媒体信息。智能体规划，FFmpeg 执行，上传插件不规划。参考输入与生成输出有独立时长限制。

## 私有规划记录（不是 API 参数）

- 模型/模式、能力核对时间、输出时长/分辨率约束。
- 各输入原始时间范围、预处理文件、最终切片及实际探测结果。
- 每段最短/最长时长、视频数量与总时长；音频独立约束、总媒体数量。
- 镜头对应、逐句台词与说话人、动作目标、预计语速、输出首尾。
- 本地校验值、COS 对象键/URL 有效期、生成任务 ID/状态。

每次请求的视频 d1…dn 均满足单段范围，n 不超数量上限，sum(d1…dn) 不超参考总时长。音频另外核算，不把两者独立上限混成一个；总媒体数量仍共同约束。提交前使用实际文件探测值，不仅检查计划值。

例如当次能力允许参考总时长 15 秒，三个 8 秒片段仍因总计 24 秒而不合法。选择代表性参考片段、缩减范围或在用户接受的方案下拆成多个请求，不是只把文件切小。示例数字不是模型永久规格。

## 边界选择

1. 先按镜头/动作/台词选窗口，再应用限制，不机械等分。
2. 尽量保持问答完整、动作到落点，边界留自然停顿，首尾有进入和完成。
3. 一次请求装得下就一次输出；超过限制才做多任务，并说明人物、商品、音色、动作跨段连续性风险。
4. 接缝余量显式标注并计入输入时长，合成时裁掉重复动作/话语，不叠两份人声。
5. 目标短于原片时选承载核心内容的窗口；台词放不下就按授权范围延长、精简或提出取舍，不静默加速。

## FFmpeg 执行

发现可用 FFmpeg/ffprobe 路径；缺失则说明依赖，不硬编码机器目录。带空格的路径作为单独参数，用参数数组调用，不拼接文件名/字幕为 shell 命令。

以下是模板，花括号必须替换为确认的值，不能直接执行：

```text
ffprobe -v error -show_format -show_streams -of json {absolute_input}
ffmpeg -nostdin -n -i {processed_input} -ss {start_seconds} -t {duration_seconds} -map 0:v:0 -map 0:a:0? -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p -c:a aac -b:a 192k -movflags +faststart {new_output.mp4}
ffprobe -v error -show_format -show_streams -of json {new_output.mp4}
```

使用解码后截取/重编码满足边界，不把 `-c copy` 关键帧粗切当逐帧准确。PowerShell 中将 `0:a:0?` 作为字符串参数。不要 `-shortest`，避免短音轨截掉画面。默认不改变时间轴/FPS；不符合输入限制才计划明确的帧率/尺寸标准化，保持比例并记录转换。

静音副本删除音轨映射和音频编码选项，改用 `-an`；不影响最终请求的 `generate_audio=true`。改后缀不是转码，静音不是视觉去真人化。

切后核对实际时长、首尾帧、A/V 时间戳/同步、FPS、宽高/比例/像素面积、文件体积和编码容器。上限边缘留帧级余量；超限就调整导出，不伪造元数据。变帧率来源尤其要核对。输入与输出不能同路径，已有输出换新文件名。

## 合成

单任务直接交付，多任务只拼接成功且对应计划的产物。先核对尺寸、帧率、音频采样率/通道等，不同编码参数不盲目流复制拼接。衔接点兼顾动作和台词完整性，淡化不能替代缺失句子。单独处理 BGM 须有授权，不引入双重背景音乐或重叠旁白。
