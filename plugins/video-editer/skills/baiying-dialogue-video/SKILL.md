# 百应切片与开场钩子成片

把内容判断与已有插件衔接起来。此 skill 负责规划、选择、审阅和记录；采集、预处理、生成、合成仍由各自工具执行。它不是新的调度服务，也不会因被调用就自动获得上传、付费或发布权限。

## 确定本次终点

从当前请求及已有授权选择，不重复询问已明确的信息：

| 模式 | 交付与停止点 |
|---|---|
| plan | 流程图、参数、素材判断标准和待补信息；不创建素材任务、上传或生成 |
| materials | 下载验证素材，交付清单与缺口 |
| handoff | 素材进入编辑器异步队列，核对导入成功与哈希；不改时间线、不渲染 |
| produce | 内容审阅、正文剪辑、按要求生成钩子、花字、预览及成片 |

调用示例：`用 $baiying-dialogue-video 规划珂欣账号的视频流程，先只做计划。`

执行示例：`用 $baiying-dialogue-video 给指定主播选素材够的商品做一条；画外提问、主播回答，原速，GPU 优先，重任务并发 1。`

按 [组件与依赖](references/components.md) 发现当前工具，读取实际工具 schema 和适用 skill。不要照抄旧版本接口或某台电脑的路径。只加载本次阶段需要的依赖。

剪辑依赖以 cardbush-plugins 的 `video-editer` 插件及同名 skill 为准，安装标识为 `video-editer@cardbush-plugins`；界面名、MCP 服务名和 Python 包名为 `video_editer`。工具前缀以当前会话实际发现结果为准。

## 输入与可调默认值

记录登录配置引用、百应子账号 ID、目标主播、商品或选品权限、素材来源范围、交付终点、期望时长、音频与速度、资源策略、生成预算和输出目录。个人资产、登录和临时 URL 留在私有运行记录中。

以下是本流程自 2026-10-17 起沿用的商品讲解剪辑默认标准。后续未重新指定时直接采用，不要求用户每次重复；新要求优先。已有本地素材时也可直接采用内容规则，不必重新采集。这些标准不扩展为所有片种的硬限制。完整规则以 [内容编排经验](references/editorial.md) 为准，参数落在流程模板中。

- 账号切换时同时更换百应素材、人物资产和音色，不能只换生成提示词。指定登录身份时显式传入，防止复用另一手机号的默认缓存。
- 用户让“选个素材够的商品”才允许在该账号内择优换商品；指定商品则报告缺口，不自行换账号或商品。
- 钩子默认画外提问 → 主播回答 → 原片展示；也可用主播强调口播或反差设问。先找具体穿着顾虑、可见差异或值得揭晓的细节，记录观众继续看的理由和正文兑现镜头；“这质感非常好”一类泛泛夸赞不单独作为默认开场，拖字、高情绪和音效只辅助已有内容。两种模式均原速 `1.0`，读 [钩子选项与表演](references/hook-options.md)。
- 当前用户的成片偏好为 **30 秒以上、60 秒以内，通常约 45 秒**。先按 45 秒估排，靠有效演示和不同重点支撑长度，不靠重复或停帧凑时长。后续明确的新时长要求优先。
- 开场保留约 2–4 秒：对话用一短问一短答，强调口播用一句短陈述或设问，随后迅速进入商品演示。重点字可自然拖长，先缩其余台词；生成时长与成片取用时长分开规划，不截断尾字或自动加速。
- 生成只用于需要补足的钩子，正文用真实切片兑现承诺；已有可用开场可直接剪。不自行另加“AI 生成开场”装饰标题，保留来源中已有或平台要求的标识。
- 本流程后续生成统一默认 **Seedance 2.0 Fast**：显式提交 `doubao-seedance-2-0-fast-260128`，能力档 `2.0-fast`，原生 `720p`、`9:16`、`generate_audio=true`。短钩子先按 4 秒生成、完整取用 2–4 秒规划；按当前能力核对参考限制，省略 2.5 专用的 `omni_reference_task_type` 和 `output_format`。不自动回退其他模型；后续用户明确改选时才覆盖。最终剪辑画布可为 1080×1920，但不能把放大的钩子称为原生 1080p。
- 正文增加卖点对应的重点镜头：讲哪个部位，就切到哪个真实演示/近景。整身、半身和细节随信息变化，避免一个主讲景别覆盖整段卖点；切点服从句意和动作完成，不按秒表空切。
- 花字按问句、回答重音、卖点、演示步骤和结尾回报分工，每次突出一个重点，保持字体与主色统一；文字跟随真实演示，避让脸、商品细节和原字幕。
- 当前用户偏好低频装饰转场：约 45 秒成片默认 1 处、最多 2 处，只用于大段落切换；没有合适位置可为 0 处。卖点切镜仍按内容正常进行，具体时长与间隔见 [转场频率](references/editorial.md#6-转场只作段落标点)。这是本流程的可调偏好，新要求优先。
- GPU 优先、重任务总并发 1 是本流程的资源预设；使用当前可用后端，不固定 NVIDIA、Intel 或某台机器的核数。

可复制 [流程参数模板](assets/workflow-plan.json)。这是编排清单，不是现有插件可直接执行的 API 请求；由调用方按实际 schema 映射。`null` 表示待解析，不能据此提交外部任务。

## 流程

1. **锁定范围与选品。** 查登录、真实子账号与商品 ID，盘点已有切片、原回放和扫描覆盖。按技术可用性与内容适用性选品；读 [节点与恢复](references/workflow.md)。
2. **备料与交接。** 用 `baiying_prepare_materials` 保存稳定 request/job ID，下载、完整解码、去重；导入编辑器时保存源哈希到 asset/job ID 的映射。素材不足按已授权来源策略补充，保持缺口可见。
3. **先成立正文。** 抽帧与听取/ASR 核对真实主播、衣服、演示、台词和时间窗。排除换人、换衣、重复话术及不适用信息。用户提供剪辑效果参考或要求实拍正文时，读 [真实演示剪辑](references/demonstration-editing.md)：检查上身、演示、细节等镜头是否覆盖卖点，先排原片台词与画面的区间表，再加花字。已有用户认可的正文先保存快照；“补钩子”不意味着重剪正文。
4. **设计钩子、花字与转场。** 读 [内容编排经验](references/editorial.md)，先写观众关心的具体问题或差异，绑定能回答它的原片区间，再选对话或强调口播。按 [钩子选项](references/hook-options.md) 记录台词、事实依据、重音/拖字、说话轮次、动作落点及可选音效，再安排取用时长和花字。单列装饰转场的内容理由、中心点与持续时间，检查数量、间隔及遮挡。若只需要规范脚本，可交给 `short-video-prompts`，显式传入关注理由、兑现镜头、所选模式、表演提示及 2–4 秒目标；其默认短片时长不覆盖约 45 秒的实拍主体。
5. **按需用真实参考生成。** 仅在本次需要且已授权生成钩子时，读取编辑器 `generated-hooks.md` 和 `reference-video-production`。从选中正文的实际片段导出参考，走当前平台支持的授权资产或经审阅预处理路线。绑定该主播脸部及音色，显式选择本流程当前模型并重新核对其能力和免费预览；历史 2.5 请求不能直接复用到 Fast。凭已有授权单次提交，持久保存 task ID 后查询原任务；直接使用已有开场时跳过生成阶段。
6. **验收后接回正文。** 比对人物、衣服、动作、台词、声音与接缝；失败不能标记通过。读取最新时间线版本后 `hook_attach`，按实际插入长度移动正文事件，补入钩子音轨和花字，核对全局静音是否误伤新声音。
7. **预览、导出与报告。** `timeline_validate` → 队列预览 → 音画检查 → 队列成片。交付本地视频、可恢复项目/任务、素材清单、内容取舍与验收记录；只报告真实编码器和实际完成的检查。

## 运行约束与完成判断

- `ready` 只表示备料目标满足；`succeeded` 只表示该工具任务成功。两者都不代表人物一致、商品正确或剪辑效果合格。
- 编辑器内导入、参考导出、渲染和失败重试走队列。ASR、外部头部处理、采集端完整解码等其他重处理不会自动共享该队列：共用资源锁，或明确串行到前一项终态且无竞争任务。云端生成等待期间不占本地重任务锁。
- 资源等待不重投；断线恢复查原 ID。需要重试时区分本地任务、下载、百应智能切片与付费生成，详见恢复表。不要把终态失败留在无限循环中。
- 所有修改保留原素材与先前认可版本，资源临时设置结束后恢复；不要为了通过任务关闭其他应用或取消资源保护。
- 用画面抽样、ASR 和响度时写清覆盖范围与不确定性；未试听不能写“已听过”或认证音色自然。最终整片重新检查音频、尾句、接缝和字幕。
- 2026-10-17 的实测依据与适用边界见 [珂欣案例](references/tested-case.md)。案例数值是证据，不是所有账号的通用配置。
