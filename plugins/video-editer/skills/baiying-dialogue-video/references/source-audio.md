# 源音频检查与无声素材排除

本页是商品讲解流程的素材入选条件，适用于所有账号、纯剪辑及生成钩子路线。用户的新要求优先。这是调用方必须执行的筛选和记录，不是已有编辑器自动拒绝无声片段的功能；`require_audio=true`、`has_audio=true`、导入成功均不证明取用区间有声音。

## 先查来源，再查取用区间

1. 下载后检查源文件是否有音轨、能否解码。短切片可扫描全段，长回放按候选窗口检查；未检查部分不计为音频已合格。
2. 选片后检查**每个实际取用区间及所用音轨**，包括头尾和内部无声段。文件其他位置有声音不能覆盖本区间无声。记录源哈希、入出点、实际解码范围、声道、峰值/RMS、静音区间和检测参数。左右声道先分别检查，避免反相相加造成假静音。
3. 将检查结果与内容用途一起判定；只有音乐或噪声不能自动判成有效讲解。需要讲解的区间还须有完整可信台词的音频/转录证据；ASR 无文字不等于静音，ASR 有文字也不等于音频可听。

| 结果 | 入选处理 |
|---|---|
| 无音轨、解码后无样本，或选区整段实际静音 | 正文排除；不要仅修改 `audio_mute` 或加音乐就判通过 |
| 极低音量、长段近静音、音轨覆盖不足、解码失败或证据不全 | 标记待核实，不计入可用正文；查原文件/音轨、重下载或换区间后重新检查 |
| 正常换气、句间停顿、动作间歇 | 检查上下文与实际时长，不把正常停顿当成整条素材无声，也不为了消除停顿切碎句子 |
| 所选范围有可听内容且符合其镜头角色 | 可入选，保存证据；渲染后仍检查有没有因静音、路由或裁切造成掉声 |

**唯一无声画面例外：钩子的全身纯展示。** 画面确属该用途，并另配通过检查的独立声音，记录画面范围、配音源区间、变速与输出时间；在成片的预期发声时段有完整可听声音，正常句间停顿可保留。例外只放行这段钩子画面，不能扩展到正文特写、穿法、配色或结尾，也不能把一条带静音片段的复合成片整体算作有声来源。人物不说话与文件没有声音分开记录。

## 使用现有检查工具

- 先读取当前工具 schema。`audio_inspect(media_path)` 测量整文件的解码响度/峰值/RMS，不支持臆造 `start/end` 参数，也不定位静音区间。
- 对已导入素材可排队 `media_prepare(operation="scan", options={"start":..., "end":...})`。当前实现的静音信号阈值为 −35 dB、持续 0.3 秒；这只是复查位置，不能把所有命中都判成素材无声。无音轨还须查元数据，不能把扫描无事件当作有声。
- 需要选区独立响度时，排队导出带音频的选区/预览后检查；`reference` 导出须显式 `include_audio=true`，避免其默认静音制造错误证据。也可在同一重任务锁下对源选区解码测量，保留真实源时间映射。不要直接并行启动多个 FFmpeg 扫描。
- 数字零静音、低音量和正常停顿分开判断。例如将低于约 −50 dBFS 的连续窗口标为近静音候选后进一步核实；阈值要记录，不能靠提高增益或一次爆点把整段静音标为合格。

每条记录包含 `asset_id/source_sha256`、`source_start/end`、`role`、`audio_stream`、`decoded_coverage`、`measurements`、`silence_intervals`、`evidence_ref`、`decision` 和 `reason`。`decision` 为 `pass`、`excluded`、`pending_review` 或 `hook_display_exception`；例外另附 `independent_audio_ref` 和输出覆盖。它们是规划记录，不是新增 MCP 参数。

## 进入时间线及导出前

先按合格的正文取用区间重新统计有效秒数、来源数和镜头角色；钩子例外不计入正文备料。缺口按现有授权补料，原文件保留但不继续使用排除片段。改取用区间、换音轨或源文件变化后重新检查，旧证据不能覆盖新选择。

最终还要按时间线逐段检测混音是否意外静音，重点复查钩子到正文、独立音轨起止和结尾；核对全局/逐片静音、源音量、轨道增益和配音覆盖。整片有音轨、平均 LUFS 正常、某处有背景音乐都不能证明每个预期有声段正常。源音频合格和最终成片有声分别记录，不能用其中一项代替另一项。
