## 决策原则

把本文件作为策略菜单，不当作固定公式。每轮组合三层策略：

- **基础阶段**：Explore、Validate、Scale、Converge、Stable、Recovery。
- **业务目标**：利润、订单、GMV、清库存、新品验证、素材验证。
- **风险覆盖层**：直播承接、低库存、高退款、审核/学习异常、数据异常。

每轮只选一个基础阶段、一个业务目标和最多两个风险覆盖层。风险覆盖层优先于增长动作，例如 `Scale + low_inventory` 应取消加预算，切换控量或暂停。把“不动作、继续观察”视为正式策略。所有数字必须服从 autonomy profile、launch authorization、account policy 和官方限制。

遵循以下优先级：

1. 账户、商品、身份和写入安全边界。
2. 余额、库存、审核、异常消耗、退款和归因完整性。
3. 用户明确的最终经营目标和预算上限。
4. 当前阶段的跑量、ROI、素材或学习目标。
5. 官方建议和 Agent 的优化偏好。

最终 ROI 不是每个时点的硬阈值。冷启动可使用较低的阶段目标获取样本，随后逐步收敛；但低 ROI 探索必须受已授权预算和止损边界限制。不要承诺最终一定达到某 ROI 或销量。

保持口径一致。平台返回 `100` 时不要自行换算成 `1.0`，除非工具规格或用户明确确认；比较基线与当前值时使用同一报表字段、归因口径和单位。

ROI 目标写工具只接受不大于 `100` 的值。用户说“100+”时，把 `100` 作为可写终点，把超过 100 的实绩作为优化结果，不构造大于 100 的目标写请求。

## 数据窗口与信号

同时维护三类窗口：

- **变化窗口**：近 1 天或最近一次投放时段，用于发现异常，不单独决定大动作。
- **判断窗口**：近 3–7 个成熟归因日，用于预算、ROI 和去留决策。
- **基线窗口**：投放前或策略变更前的可比 7 天；优先匹配星期、直播时段、商品和营销场景。

每次判断至少检查：消耗、曝光、点击、CTR、订单、成交额、ROI、成交成本、学习状态、审核状态、预算利用率、库存；可取得时再检查退款相关净收益。

用样本可信度约束动作：

- 没有消耗：先检查审核、状态、余额、预算、出价、商品和流量资格。
- 有消耗无订单：达到用户止损或充分样本前保持小额探索；达到边界后降预算或暂停。
- 少量订单：标记低置信度，不因单笔大订单立即放量。
- 归因未成熟：记录待观察，不用当日 ROI 覆盖成熟窗口判断。
- 报表截断：缩短日期、分页、减少字段；不要根据不完整列表排名或写入。

“销量明显增长”优先采用用户给定阈值。未给定时同时报告订单量和销售额相对基线的实际增幅，不擅自设定成功线。

## 阶段状态机

### Explore 探索

目标：验证商品、素材、身份、场景和基础转化能力。

- 使用小范围商品、计划和广告；预算不超过创建授权与账户策略。
- 阶段 ROI 可低于最终 ROI，优先获得可信转化样本。
- 不因短时零单频繁改预算；先检查学习、审核和流量资格。
- 达到样本要求且存在可重复转化时进入 Validate；触及止损、库存或异常边界时进入 Recovery/Stop。

### Validate 验证

目标：确认结果不是偶然，并找出稳定素材、时段和商品组合。

- 在相近预算下复验，尽量一次只改变一个主要变量。
- 同时要求阶段 ROI 可接受、订单/销售额为正且波动没有失控。
- 连续成熟窗口成立时进入 Scale；结果分化时保留赢家并淘汰弱组合。

### Scale 放量

目标：扩大订单和销售额，同时控制 ROI 回撤。

- 对高置信度赢家小步增加预算；具体幅度服从策略边界和平台最小变更量。
- ROI 达标但预算未花出时，先诊断出价、素材、受众、状态和场景，不只加预算。
- 销量增长而 ROI 仍在阶段下限之上时继续；ROI 急跌或销量不增时停止加量并回退上一稳定预算。

### Converge 收敛

目标：从跑量目标逐步回到最终 ROI，同时尽量保存新增销量。

- 分步提高 ROI 目标，不一次跳到最终值。
- 提高 ROI 后先等待成熟窗口；避免同轮大幅改 ROI 和预算。
- 若 ROI 提升但订单断崖下降，回退一个档位并诊断流量约束。
- 成熟窗口同时达到最终 ROI 和销量增量目标后进入 Stable。

### Stable 稳定

目标：维持最终 ROI 与增量销量，持续寻找小规模新增量。

- 维持稳定预算锚点；只对新证据做小幅调整。
- 轮换疲劳素材，避免频繁触碰稳定赢家。
- ROI 或销量连续恶化时进入 Recovery，不用单日波动重置全部策略。

### Recovery 恢复

目标：限制损失并定位异常。

- 先查审核、学习、素材疲劳、库存、余额、退款、数据缺失和平台状态。
- 回退至最近稳定预算/ROI 档位；必要时在授权范围内降预算或暂停。
- 修复后用小预算重新 Validate，不直接恢复峰值预算。

## 场景策略

### 新商品或冷启动

主策略：`cold_start`；辅助策略：`creative_test`。

- 从已授权且库存满足边界的商品中选择少量候选。
- 优先测试商品/素材/场景组合，不同时扩很多变量。
- 使用学习状态和订单样本决定晋级；无数据先排查流量资格。
- 退出条件：形成稳定转化进入 Validate，或达到止损进入 Recovery/Stop。

### 低 ROI 跑量后收敛

主策略：`roi_converge`。

- 把锁定 target ROI 视为最终目标，不把它机械应用到探索期每个窗口。
- 根据当前成熟 ROI、订单增幅和预算利用率设置阶段目标；只通过分析工具显式传入，不反复改锁定档案。
- 跑量成立后逐级提高 ROI 目标；每一级等待归因成熟。
- 最终判断必须同时看 ROI 和相对基线的订单/销售额增幅。

### 高 ROI 但跑量不足

主策略：`scale`。

- 先判断是预算受限、出价/ROI 目标过紧、素材供给不足还是流量场景不匹配。
- 预算已花满且结果稳定时小步加预算；预算花不出时优先检查 ROI 目标、出价、素材和状态。
- 放量后 ROI 可合理回撤，但不得越过用户最终边界或策略止损。

### 跑量高但 ROI 下滑

主策略：`recovery`；辅助策略：`roi_converge`。

- 分解流量成本、点击、转化、客单价和退款影响，找出下滑环节。
- 停止继续加预算，回退最近稳定档；优先处理拖累对象而非全账户一刀切。
- 连续成熟窗口恢复后再进入 Validate/Scale。

### 稳定利润扩量

主策略：`stable_profit`。

- 保护已达到最终 ROI 且有稳定订单的组合。
- 将新增预算优先给高置信度、库存充足、素材未疲劳的赢家。
- 用小比例探索池测试增量，避免全部预算同时进入未知组合。

### 素材测试与疲劳

主策略：`creative_test`。

- 使用素材报表和 `qianchuan_analyze_material_fatigue` 比较 CTR、ROI 和趋势。
- 通过 material decisions 保存 winner、test_candidate、fatigue 等结论。
- 测试时尽量保持商品、预算和场景可比；不要因单日 CTR 波动淘汰素材。
- 疲劳成立时先轮换/补充素材，再决定是否调整预算。

### 直播预热、直播中和复盘

主策略：`live_ramp`。

- 预热期检查抖音号权限、商品、素材、余额与开播时段，使用小预算验证进房与商品点击。
- 直播中使用短窗口监控异常，但写动作仍服从冷却和预算边界；区分流量成本、进房、商品点击和成交环节。
- 直播后等待归因成熟，按场次保存 review；不要用整日数据掩盖直播时段表现。

### 清库存

主策略：`clearance`；辅助策略：`inventory_protect`。

- 只有用户经营目标明确为清库存时使用；不能从库存偏高自行推断。
- 可在授权范围内接受较低阶段 ROI 换取销量，但不得忽略毛利、退款和最低余额。
- 库存接近下限时停止放量，避免超卖或把不可投商品继续留在策略池。

### 大促或限时冲刺

主策略：`scale`；风险覆盖层：`low_inventory` / `anomaly`。

- 先确认活动起止时间、预算池、利润底线、库存保护和结束回撤条件；没有明确活动目标时不自行进入冲刺。
- 使用可比活动时段基线，区分自然增长与广告增量；峰值期可更积极但仍服从余额、库存、冷却和承接能力。
- 活动结束立即回到常规阶段，核验预算与 ROI 目标，避免峰值设置滞留。

### 低库存保护

主策略：`inventory_protect`。

- 降低或停止对低库存商品的新增预算与新建计划。
- 把预算转给同授权范围内、库存充足且表现可信的商品；没有替代品时保持保护，不扩大商品白名单。

### 高退款或低净利润

主策略：`recovery`。

- 使用毛利率、退款率和额外成本率计算利润安全 ROI；报表表面 ROI 不能替代净收益判断。
- 优先削减高退款且成熟净 ROI 不安全的组合，保留低退款的可验证赢家。
- 用户未明确更新经营参数时，不从单次报表反向修改锁定档案。

### 审核拒绝、冻结、删除或无活跃投放

主策略：`recovery` 或 `cold_start`。

- 审核拒绝：读取拒绝原因，形成修正预案；不盲目重复提交。
- 冻结/删除：不对旧对象执行预算优化；需要新投放时重新发现资产并走完整预演。
- 无活跃投放：不要用历史数据触发写入；按新建流程重新开始。

### 搜索、信息流与全域

- 信息流重视素材、学习和规模；搜索重视搜索词意图、转化与有限配额；PC 千川全域使用 `UNI_AWEME` 直建链路，不要求标准 Campaign，随心推全域订单不作为替代。
- 不把一个场景的枚举、素材或阈值直接复制到另一个场景。
- 跨场景比较时分开归因口径，再决定预算组合。

### PC 千川全域多计划细分

适用：需要比较不同商品、价格带、库存状态或成熟度，而不是让多个商品在同一计划中互相稀释信号。

- **Core 池**：单独放已验证、库存稳定、素材供给充足的主推商品；目标是稳定 ROI 与成交。
- **Growth 池**：单独放已有初步转化但仍需验证容量的商品；目标是判断能否扩量。
- **Explore 池**：只放一个明确假设（新品、商品差异或素材供给）；目标是得到可解释样本，不承担最终 ROI。

创建计划前先以官方详情、审核建议、全域资格、预算利用率和报表排查零消耗原因。零消耗时，拆分本身不是有效修复；先处理审核、资格、排期、商品或素材供给问题。

每个计划在 Explore/Validate 默认单商品；只有商品同质、价格带接近且库存/素材条件一致时才允许小组计划。计划命名必须编码池类型、商品/分组、策略阶段和日期。不要把同一商品的同质计划同时投放来抢量；除非用户明确要求并能解释独立变量。

总预算不是把每个计划的预算相加后自动合法：同时检查用户总额、每计划官方最小日预算、Launch Authorization 的 `max_initial_ad_budget` / `max_ads_per_day`、账户余额及 Account Policy。创建次数不足时停止，要求用户显式更新锁定边界；不要用编辑、复制或原始工具规避。

先让各计划经过最小观察窗口；比较计划级 ROI、订单、GMV、消耗、预算利用率、库存与素材状态。只有有样本的赢家才能进入 Growth/Core；无消耗计划进入 Recovery 诊断。乘方升级只在已有稳定、已暂停且用户明确点名的计划上单独评估，不作为零消耗或多计划细分的替代方案。

## 多计划组合

把计划分成三个池并动态调整：

- **核心池**：成熟赢家，承担稳定 ROI 和主要成交。
- **增长池**：刚通过 Validate 的对象，承担可控放量。
- **探索池**：新商品、新素材或新场景，预算最小且有明确止损。

优先从弱对象回收预算，再分配给有容量的赢家；不要为了“用完预算”给无证据对象加量。跨计划重分配时校验调整后总预算、单对象上限、24 小时累计增量和库存。

余额或总预算受限时，依次保护核心池、已验证增长池和最小探索池。不要把全部预算集中给高 ROI 但无规模的小样本对象；低于最低余额边界时停止新建和放量。

冲突处理：

- ROI 达标、销量不增：诊断跑量约束，不宣称成功。
- 销量增长、ROI 未收敛：保持或小步回退，进入 Converge，不继续无条件放量。
- ROI 与销量都改善：进入 Scale，但仍小步调整。
- ROI 与销量都恶化：进入 Recovery，停止新增量。

## 动作选择

优先选择最能验证当前假设的最小动作：

- 预算：标准对象用 `qianchuan_update_budget`；全域对象用 `qianchuan_update_uni_promotion_ad_budget`
- 出价：`qianchuan_update_bid`
- ROI 目标：标准对象用 `qianchuan_update_roi_goal`；全域对象仅在详情确认支持 ROI2 时用 `qianchuan_update_uni_promotion_ad_roi2_goal`，不得对 `SMART_BID_CONSERVATIVE` 设置 `roi2_goal`
- 状态：标准对象用 `qianchuan_update_ad_status`；全域对象用 `qianchuan_update_uni_promotion_ad_status`
- 创建：PC 千川全域用 `qianchuan_create_uni_aweme_ad` 直接创建；标准链路仅在官方仍支持时使用 `qianchuan_create_campaign`、`qianchuan_create_ad`
- 多计划创建：按 Core / Growth / Explore 的单商品或同质小组拆分；每次创建仍单独 `preview_launch_plan`、查重、创建、回读和 strategy review，不批量提交
- 素材结论：`qianchuan_create_material_decision`

每次写入都提供具体 reason，说明数据窗口、证据、阶段和预期；写后读取官方状态核验。超时或结果不明时先对账，不直接重试。

预算动作还要满足两个同时存在的约束：提供 `previous_budget` 时绝对变更至少为 100 元；账户策略通常还限制最大变更比例。先计算 `previous_budget × max_rate`，若小于 100 元则本轮没有合法预算调整，不动作并报告冲突。不要改用 `qianchuan_update_ad` 绕过专用预算工具。

通用 `qianchuan_update_campaign` / `qianchuan_update_ad` 不会替 Agent 完成全部 launch authorization 校验。只有专用工具无法表达且锁定边界逐项复核通过时才考虑使用。`qianchuan_update_ad_status` 的 `DELETE` 不得自主使用；止损优先使用可逆的 `DISABLE`。

## 复盘状态格式

每个决策周期调用 `qianchuan_create_strategy_review`。在 `source_json` 中使用稳定字段，便于下一轮恢复：

```json
{
  "strategy_version": "multi-scenario-v1",
  "stage": "scale",
  "objective": "orders",
  "risk_overlays": ["low_inventory"],
  "scope": {"campaign_ids": [], "ad_ids": [], "product_ids": []},
  "final_target_roi": null,
  "stage_target_roi": null,
  "baseline": {"window": null, "orders": null, "revenue": null, "roi": null},
  "evidence_window": null,
  "attribution_mature": false,
  "action": null,
  "rollback_anchor": {"budget": null, "roi_goal": null},
  "next_check_at": null
}
```

把具体观察写入 `worked`、`failed`、`suggested_changes` 和 `next_checks`。不要保存 token、API key、HMAC secret 或完整授权头。
