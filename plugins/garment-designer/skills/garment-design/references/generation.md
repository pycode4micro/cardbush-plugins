# 用户确认后的生成与分析

## 生成

1. 确认用户已看过并认可当前版本，包括几何轮廓与未能在矢量图表现的材质描述。面板“确认此版本”消息视为该版本的用户确认；如果有新修改则重新展示新版本。
2. 发现现有生图工具与能力。优先复用已配置的 Seedream，用户指定其他服务时用指定服务。读取当前能力/schema；不硬编码模型、图片数量、尺寸、掩膜能力或参数名。没有可用服务时保留设计并明确“尚未生成效果图”，不要伪造结果或擅自安装/付费。
3. 用 `garment_render prepare`，传准确 revision、唯一 request_id、`confirmed_by_user:true`。若用户面板已提供 job_id，直接读取该任务，不再创建一次。工具只做本地导出，无付费调用。
4. 读取任务中的 prompt、overview、正反面 views、部位 detail/mask、可选参考图。overview 为主控制图；按生图服务限制加入关键部位特写。若图片数有限，优先保留整体，再选重要细节。不能悄悄舍弃用户必须保留的细节；需要时用 SVG 排版把特写合成一张参考板，仍不使用生图生成中间素材。
5. 适配服务的真实输入限制，可先调用无费用的请求预检。例如 Seedream 当前提供 `seedream_capabilities`、`seedream_preview_request`、`seedream_generate`；以实际发现结果为准。通过 `local.reference_images` 传**同一主机**的 PNG 绝对路径，文本放 `request.prompt`，不要将 SVG 当成支持的位图。默认请求一张清楚的整体产品效果图；用户指定上身/场景/多视图时才相应调整。先检查参考路径是否与生图服务共享文件系统，不共享时使用宿主明确支持的传输或数据 URI，不能让服务猜路径。
6. 预检通过后，`garment_render claim`。只有本次成功返回 `proceed:true` 才可提交一次生图。重复领取会被插件拒绝。生成期间新设计不会改变已冻结的任务；新版本需要另一个确认任务。
7. 调用选定生成工具一次，展示其实际输出。用 `garment_render attach` 保存真实本地 PNG/JPEG/WebP，传 provider 名称。生成工具只返 URL 时先检查它是否支持本地保存；遵守宿主的图片访问与下载规则，无法取得本地文件时如实说明，不伪造 attach。
8. 明确失败用 `fail` 记录简短原因；超时或失去响应可能已产生计费，请核对服务端已有任务/文件，不能自动重投。恢复同一张图片可再次 attach，幂等保存。要新生成一版，先取得新的用户授权并使用新 request_id。

PNG 是矢量稿的本地渲染，不是先行生图。mask 是辅助导出文件，不表示当前服务一定支持区域编辑。普通图像生成会有形状/文字/颜色漂移；插件没有把概率生成变成精确 3D 模拟。

## 分析与修改

1. 用 `garment_review context` 读取**实际成图**、对应确认版矢量图和部位描述，不能只读文件名推测图像。由宿主已启用的视觉模型分析；本插件不含第二套视觉模型/API key。
2. 检查轮廓比例、部位数量、位置、前后关系、颜色、可见材质效果、装饰和用户必须保留的细节。对没有显示的背面、不可见结构、精确成分/工艺明确“不确定”。
3. `garment_review save` 保存 findings：`deviation` 是与原要求不符；`suggestion` 是可选审美建议；`uncertain` 是证据不足。每项尽量标明 partId，observation 描述可见证据，proposal 写可执行修改。不要把个人审美写成客观错误。
4. 展示最重要的差异，由用户选择继续调整。需要改款时先读取**当前**设计，再按用户选择修改矢量及文字；不能用旧生成版本覆盖后来修改。只是成图偏离设计时可以保持矢量稿并收紧描述，或使用服务实际支持的参考图编辑能力。新的付费生成仍需用户确认。
5. 若视觉模型无法读取成图，直接告诉用户暂不能分析；保留图片和设计，不输出假分析。已有报告可读取展示，不重复覆盖。
