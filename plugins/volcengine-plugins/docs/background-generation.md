# 插件后台生成与批量等待

长任务由插件执行，宿主复用现有后台只读工具能力；无需改 CardBush，也不需要子 Agent 负责轮询。当前共 34 个工具，新增两个入口，原同步入口兼容保留。

## 生图

优先调用 `seedream_create_task(request, request_id, local)`。`request/local` 与原生图接口相同，`request_id` 是本次生成意图唯一的 8～128 位字母/数字/下划线/连字符标识。

- 返回本地 `task.id` 和 `queued`，表示插件已接单，尚不是生成成功，也不表示火山已受理。
- 同一机器、同一用户状态目录内最多同时执行 2 个请求，最多接收 32 个未结束任务；不需要 Redis 或额外服务。多个 MCP 进程共享并发上限与重复提交记录。
- 丢失响应时用**同一个 request_id 和原参数**恢复回执。相同键不同参数会拒绝；要有意生成另一版才使用新键，不用新键重试不明确的付费请求。
- 预检时快照输入与本地图片字节，队列等待期间不会重新读取变化后的素材。输出、用量、URL/本地路径仍使用原生图结果结构。
- 状态与结果保存到用户目录 `.volcengine-plugins/image-jobs`，按凭据/接口隔离；不保存 API Key、原提示词和输入素材。更换 API Key 后不自动关联旧记录。结果可能含临时媒体 URL，此目录应保持私有。

旧 `seedream_generate` 保持同步返回，供依赖原返回结构的调用使用；独立长任务优先新入口。

## 统一等待

```json
{
  "tasks": [
    {"kind": "seedream", "task_id": "返回的本地图片任务ID"},
    {"kind": "seedance", "task_id": "返回的火山视频任务ID"}
  ],
  "timeout_seconds": 60,
  "mode": "any"
}
```

以上参数传给 `generation_wait_tasks`。`kind` 还支持 `music`、`enhance`、`subtitle`，分别使用各创建接口返回的原任务 ID，不改变已有云端任务架构。

- `timeout_seconds=0` 只查一轮；1～120 秒在插件内等待。最多 32 个任务、4 个并发查询，视频/超分/去字幕至少隔 30 秒，音乐至少隔 10 秒；服务端建议更长间隔时遵守它。
- `mode=any` 有任务结束或查询出错就先返回；`all` 等所有任务。保留部分结果，已完成任务不反复查询。
- `status=ready` 只表示有可处理结果，**不等于全部生成成功**。逐项检查 `succeeded/completed`、失败或 `query_error`。后续只等剩下的未完成 ID，避免已完成项让 `any` 立即反复返回。
- `status=timeout` 表示等待预算用尽，生成仍可能运行；查询错误不自动循环重试，也不触发重新生成。
- 此工具只查状态和读取既有结果，不下载、不重提、不取消生成。成片继续由原下载工具落盘；生图结果位于 `items[].observation.task.result`。

## 接入宿主已有后台等待

先加载完整工具 schema。宿主暴露 `start_mcp_tool` 时，把 `generation_wait_tasks` 的实际工具名和上面的参数交给它，并设置：

```json
{
  "max_wait_ms": 600000,
  "repeat_while": {"path": ["structuredContent", "status"], "equals": "timeout"}
}
```

这样由插件在每次有界等待中控制查询频率，宿主在超时后续等，模型可以继续独立工作；没有其他工作时使用宿主已有等待能力。只在结果交付后继续判断，中间 `queued/running` 不要求 LLM 反复调用。宿主完成结果按已有机制追加，插件不改会话历史或系统前缀。

没有后台工具的客户端仍可直接调用本工具减少模型轮询，但这一次工具调用会等待返回。插件不能自行唤醒已结束的对话。

## 中断与重启

取消状态等待只停止查询，不能据此宣称云端生成已取消。MCP 进程结束会中断它持有的本地生图调用：排队未发送的是 `interrupted`，已经准备发出/发出但未保存结果的是 `unknown`。重启后可读已保存回执；**不会自动重放这些任务**。不明确的请求先查火山用量/记录，再决定是否重新生成。正常完成的结果可跨插件重启读取；同步接口没有的云端查询能力不会因本地队列而凭空出现。

测试使用虚构凭据和模拟生成，覆盖队列去重、多个实例并发、真实进程异常退出、部分完成、查询取消和实际 MCP stdio 握手，不产生付费调用。
